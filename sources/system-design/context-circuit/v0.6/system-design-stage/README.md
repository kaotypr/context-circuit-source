# System-design stage — design

The v0.6 scope that makes a **System Design** a first-class, optional lifecycle
stage between Product Knowledge and Plans. v0.6 is a **delta on v0.5** — see
[../README.md](../README.md) for the version index and [../../v0.5/](../../v0.5/)
for the base design.

## Reading order

1. [design.md](./design.md) — the overview: the capability, the lifecycle
   position, principles, and fixed decisions.
2. [product-knowledge-boundary.md](./product-knowledge-boundary.md) — the crux:
   how a System Design differs from Product Knowledge and flows into it.
3. [lifecycle-and-gates.md](./lifecycle-and-gates.md) — where the stage sits, its
   acceptance gate, how it grounds plans, and how completion reconciles back.
4. [workspace-layout.md](./workspace-layout.md) — where a system design lives in a
   workspace, the three-tier document layout, authoring, and diagrams.
5. [schema-and-contracts.md](./schema-and-contracts.md) — the contract deltas: the
   plan grounding reference, the acceptance record, conversational actions, invariants.
6. [examples.md](./examples.md) — a worked example and the acceptance criteria.

## Authority

This scope adds no owner and duplicates no rule; it specifies intent and points to
the canonical owners under `wrapper/`. Contract deltas are summarized in
[schema-and-contracts.md](./schema-and-contracts.md).
