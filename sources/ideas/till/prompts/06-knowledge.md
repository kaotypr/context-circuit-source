# 06 — Close the knowledge loop

Shipped work is not automatically "what the project knows". You accept or defer
updates. Unresolved follow-up can block the **next** overlapping Standard or
Critical change.

---

## 33. knowledge-debt-blocks-next-plan

**When:** Invoice list (or storage / schema) was delivered, and it asked you to
fold that into project knowledge, and you have not done that yet. You now ask
for the next overlapping change (search, filter, detail page).

**Say:**

1. `The invoice list is finished. Please start the invoice search work now.`
2. `If the project notes need a decision first, tell me what is pending and leave the follow-up on hold.`
3. `Thanks.`

**You should see:** The next overlapping work is held. It tells you what is
pending in plain language. It does not silently accept knowledge, and it does
not start the next build.

---

## 34. reconcile-and-proceed

**When:** Same situation as case 33, and you are ready to accept the notes.

**Say:**

1. `You said the invoice-list change needs a decision before the search work. What is it?`
2. `Yes — record that list-and-filter behavior as how the project works, then the search work is clear to go.`
3. `Thanks.`

**You should see:** You accept the update; the hold clears; the next change can
proceed (still subject to its own approval if it is a new decision). It does
not invent extra decisions.
