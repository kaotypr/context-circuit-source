# Context Circuit 2.0.0-rc.7

A candidate for 2.0.0-rc.6 that moves a repository's base branch to the machine
it describes, and changes what a subagent is told and what the coordinator has to
write to dispatch one. Records are unchanged. A workspace configuration file is
not, and is not converted for you. The v2 description in 2.0.0-rc.1 still stands.
This template recommends CLI `2.0.0-rc.7`. Git is required. No Go or Python
runtime is.

## Breaking: a base branch belongs to the machine

A base branch describes one checkout. A machine following a release branch and a
machine on the default cannot share a single value, yet `base_branch` sat in
`workspace.yaml`, which everyone shares. It now lives in that machine's binding
in `repositories.local.yaml`, beside the path it applies to. Worktree preparation
and order derivation start from it and fall back to the shared default branch
when a binding records none.

`workspace.yaml` keeps what everyone does agree on: a repository's `url`, taken
from the checkout's origin unless `--url` names one, and its `default_branch`.
`repo base` writes this machine's binding; the new `repo remote` writes the
shared pair. `repo connect` accepts `--url` and `repo init` accepts
`--default-branch`. A URL embedding a password is refused rather than written to
a shared file, because Git's credential helper is where that belongs.

A workspace initialized by an earlier candidate carries `base_branch` in
`workspace.yaml`, where it is now an unknown key. Nothing converts automatically.
Reading such a file names the move rather than reporting a corrupt file, so the
error says where the value went and what a repository entry holds instead. Move
each repository's base branch into its binding with `repo base`, and record the
shared URL and default branch with `repo remote`.

## Breaking: a planner takes no `--task`

`agent dispatch --role planner` now refuses `--task`, and `--task` is optional
for a worker. A planner is dispatched against a whole approved intent and a
worker against the plan quoted in its brief, so a task on either could only
restate what the brief already carried — and a required flag left the
coordinator nothing to write but that restatement. One observed planner task
asked for "the plan shape: task order, dependencies, risks, and exact checks",
which is the list of headings the planner was already answering under, followed
by a summary of the intent quoted three paragraphs above it.

A role no record assigns still states its assignment: an explorer's question and
a reviewer's criteria are required as before. So is the one slice a worker owns
when several share a plan, which is named in `--task` and nowhere else. A brief
carries no task section when no task was given.

## A brief that left how to read it open

A read-only role received a working directory and no statement of what it could
do there, because ownership was written only for roles that change files. On a
host offering GUI automation and web search that leaves a question open, and one
planner answered it by driving an editor's interface through thirty-five
accessibility-tree calls to read files in its own working directory, then
searching the public web for a repository sitting on disk.

Ownership now reaches every role. A read-only brief says to read and search the
files in the working directory directly, to drive no other application, and to
consult nothing external, because what the task needs is that directory and the
brief. An implementer's ownership is unchanged.

This reduces the chance rather than removing it. The same role definition, brief,
model, effort, and host produced two runs that read the repository with ordinary
file commands and one that did not; across every subagent session on the machine
that observed it, two of seventy-eight touched a graphical interface at all. The
cause was a tool choice, not a missing rule, so an instruction can only shift the
odds — and give a later reader a rule that was visibly broken rather than a
silence to interpret.

A related claim is retired. Read-only roles were told "You cannot run anything",
which is true where a host enforces it and false where one does not: a Codex
agent spawned against a read-only role definition was observed running at full
access, with that definition's model, effort, and instructions all in force and
its sandbox mode alone dropped. Nor would that sandbox have covered much, since
it governs file writes rather than a host's other tools. The instruction now
states the conduct it always wanted — run no tests, linters, or builds; a check
you name is one you read, never one you saw pass — which holds either way and no
longer reads as forbidding the ordinary file reading that planning requires.

## What changed

- **A wait that was a poll loop, and guidance that blamed the wrong thing.**
  2.0.0-rc.6 said that wrapping a wait in `exec_command` turned it into a poll
  loop. A coordinator that followed the advice exactly — calling the wait
  directly, with a timeout measured in minutes — still paid seventeen polls
  carrying the whole session, about half of that session's total tokens, for two
  subagents that ran ten minutes between them. The park comes from the exec cell,
  not from `exec_command`, and the knob is the yield on the resume rather than
  the timeout on the wait. The cost grows with how long delegated work takes,
  which is the wrong direction for a mechanism whose purpose is to delegate more,
  so the instruction now asks for the longest yield the host permits instead of
  its default.
- **A coordinator hunting for a tool signature.** Naming the spawn and wait tools
  in 2.0.0-rc.6 was not enough: the specification says what to pass, but on a host
  whose subagent tools carry no visible schema it does not say what the arguments
  are called, and three sessions in a row queried the registry to find out. The
  guidance now carries the call itself, including that the spawn passes only the
  agent type and the message. A role definition already holds the model and
  effort and refuses to have them changed, and a role set to inherit is one meant
  to take the parent's model, so passing either on the spawn is wrong in both
  directions. Releasing a finished agent is named too, since a completed one stays
  open against the concurrency limit until it is closed.
- **A planner answering under headings the record could not hold.** A planner
  returned evidence and uncertainties, and the instruction asked for both to be
  transcribed, but a plan record ships three headings. The two without a slot were
  dropped in silence. A planner now answers under verdict, approach, tasks and
  order, risks and checks, and plan shape; the three that transcribe have
  somewhere to go, and tasks and order already requires each task to name its
  repository and its paths.
- **A prohibition the coordinator kept restating.** Every observed worker task
  ended by forbidding push, pull request, and merge — two of which the brief
  already forbade under ownership. The worker's own instructions now name all
  three, so the coordinator has nothing left to add.

## Upgrading

Run `agent setup` after installing. The explorer, planner, and worker
instructions all changed, and native role definitions embed them, so a host still
holding the previous definitions briefs its agents with the previous text. A
definition you customized is preserved and reported rather than overwritten.

A caller dispatching a planner with `--task` is refused and told why. A caller
passing `--task` to a worker is unaffected; one that omits it now gets a brief
without a task section, which is the intended shape for a worker that owns its
whole plan. Explorer and reviewer dispatches are unchanged.

Plans written by earlier candidates keep any evidence or uncertainties they were
given. Nothing is rewritten.

## Candidate status

Deterministic tests cover the base branch's move: a binding that records one, a
binding that does not and falls back to the shared default, the shared pair
`repo remote` writes, the refusal of a URL carrying a password, and the message
an earlier workspace's `base_branch` key produces. They also cover the refusal of
`--task` on a planner, a worker brief
composed with and without one, the ownership section a read-only brief now
carries and the phrase it no longer carries, the delivery acts named in the
worker's instructions, and the brief composition and record quoting carried from
earlier candidates. A test asserting the absence of a task section was found
matching the quoted plan's own `## Tasks and order` heading and now matches the
section exactly.

Whether a coding host passes a longer yield on a wait, calls the spawn tool
without querying for its signature, stops writing a task it was no longer asked
for, or reads a repository with ordinary file commands rather than an editor's
interface, is established by no test here: those are instruction changes and are
unproven in that sense. The last of them is a change of odds and not a guarantee,
for the reasons given above. Exercise the flows you rely on before depending on
this release.
