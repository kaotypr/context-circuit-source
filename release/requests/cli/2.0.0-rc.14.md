# Context Circuit CLI 2.0.0-rc.14

The seed this binary carries is the workspace and nothing else. What the
published template repository shows a visitor is that repository's business, and
it is no longer embedded here.

## Changed

`template export` writes four files fewer. `README.md`, the license under
`.context-circuit/`, and the two images beside it are gone from the manifest,
so an exported seed is the workspace a project keeps and nothing about the
product that produced it.

`init` writes `README.md` itself, from a seed of its own that is not part of the
export. It renders three generated spans between markers:

- the title, as `Context Circuit - <workspace name>`
- the version badges, read from the two stamps this workspace holds rather than
  from whatever was published since
- the purpose, from `--purpose`

The rest of the file is prose about what the workspace is, what Context Circuit
is, and where to look — written to be edited or thrown away by the project that
now owns it.

`init` no longer refuses when a `README.md` is present. It is not template
material any more, so a project that already has a front page is not a project
that failed a precondition. An existing file with the markers has those spans
refreshed; without them it is untouched. Neither case overwrites prose.

## Compatibility

Records written by 2.0.0-rc.4 and later are read unchanged, and this release
changes no record format, no schema, and no command surface. A workspace
initialized by an earlier CLI keeps every file it already has: nothing is
removed from a workspace on upgrade, by this CLI or by anything else.

The only behavior an existing workspace will notice is that re-running `init` is
no longer refused by the presence of a README — and it still refuses for every
reason it did before, including existing workspace data, existing members, and
any other seed file that differs from what it would write.
