# Context Circuit CLI 2.0.0-rc.13

Released before the CLI had a release request of its own, and recorded here when
it got one. The notes published with `cli-v2.0.0-rc.13` were `CLI.md` — a
description of what the CLI is, identical in every release. This is what that
version actually changed.

It is the first CLI release built and tagged from
[context-circuit-source](https://github.com/kaotypr/context-circuit-source),
where the Go source is. Releases through 2.0.0-rc.12 are on the template
repository under `context-circuit-cli-v*` tags, and the tag here is `cli-v*`.

## New

`knowledge` is a new command group: a workspace can mount a knowledge repository
it does not own, read-only, retrieved alongside its own notes and never
reconciled here. `status` grows a `knowledge_repositories` section when a
workspace has any.

`check` reads a note's reviewed date against the code it anchors to rather than
against the calendar, and every finding now names what discharges it — the one
place this CLI used to leave a caller to improvise, in the state where
improvising costs most.

`member tone` records the register a member writes in. `init` titles a new
workspace's README with that workspace's own name.

## Breaking: a workspace recording `cli_registry` does not load

The field is gone from the schema, and `workspace.yaml` rejects a key it does
not know. That is the existing contract, not a new strictness, but it means a
workspace that recorded a mirror stops at the first command rather than at the
first install:

```
workspace.yaml: [6:1] unknown field "cli_registry"
   5 | relationships: []
>  6 | cli_registry: "https://gitlab.example.com/acme/context-circuit"
```

Delete the line. Nothing replaces it and no state is lost: the value was read
only when installing. The installers drop `--gitlab-url` and
`CONTEXT_CIRCUIT_GITLAB_URL` with it, so a script that passed either is refused
by name rather than quietly ignored. Installation reads GitHub directly.

## Corrections

- An empty command argument crashed. `context-circuit-cli ""` reported the
  unknown command, then went looking for its first word to suggest a help
  topic, and there is no first word.
- `member band` with no `--band` cleared the member's block instead of refusing.
  Zero is the documented way to clear a band, so an omitted flag was
  indistinguishable from a deliberate `--band 0`.
- `record create` rendered a created record's body to a person as a YAML scalar,
  which arrives as a single escaped line. The reservation and path now lead and
  the body follows as itself.
- One-shot Git configuration inherited from the environment reached the CLI's
  own Git commands: a host that ran `git -c` exports it to everything
  underneath. `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` are untouched — a
  person sets those to isolate an environment, and no Git operation sets them.
- `install.sh` demanded a value before it read the option name, so `--help` was
  refused and an undefined option was reported as one missing an argument.

## Compatibility

Records written by 2.0.0-rc.4 and later are read unchanged.
`knowledge_repositories` and a member's `tone` are optional, so a workspace from
2.0.0-rc.12 loads without them. An older CLI cannot read a workspace that has them: unknown fields
in structured records are errors, which is why each workspace pins its CLI
version.
