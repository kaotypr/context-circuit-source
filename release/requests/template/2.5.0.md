# v2.5.0

This workspace version pins CLI 2.5.0. No record's content changes; the
pinned CLI renames an existing `intent/archive/` or `plans/archive/` to
`_archive/` on its first changing command.

Every workspace now carries a launcher: `.context-circuit/cli`, run as
`sh .context-circuit/cli COMMAND …`, and `.context-circuit/cli.ps1` for Windows
PowerShell or cmd. It runs exactly the version `.context-circuit/CLI_VERSION`
pins from the installers' version store, never a CLI found on PATH, and when
that version is not installed it refuses and names the install step. It
refuses a `--workspace` that names another workspace. It looks in the
installers' default directory, or in `CONTEXT_CIRCUIT_BIN_DIR` when that is
set. `.context-circuit/.gitattributes` keeps `cli` at LF and `cli.ps1` at CRLF
line endings on every checkout.

`.claude/settings.json` allows both launcher commands, so Claude Code runs them
without a prompt. A workspace that already has the file merges the two entries
into it entry by entry, keeping every entry it added, rather than replacing it.

Every instruction, skill, and command reference now calls the launcher. When
CLI output warns that the workspace pins another version, or refuses a change
for that reason, the agent acts on none of it and runs the command again
through the launcher. A CLI from another release line is a different product
for the workspace, never a substitute.

"The latest release" and "a later tag" mean the latest and later ones on the
workspace's own release line: a stable pin updates among stable releases, and
a `<label>` pin among that label's releases. Moving to another line is a
template change a person names by its exact tag.

`AGENTS.md`, the record and command references, and the `cc-complete` skill
describe grouped records and the archive: a record may sit in one level of
group folder with `_archive/` above or below it, `record list` and `status`
show your own work first, and `record archive` moves your own finished records
under `_archive/`. After completion the agent offers to archive, and a no
changes nothing. One person runs the first changing command that renames
`archive/` to `_archive/`, commits and pushes it, and the rest install the
2.5.0 CLI before pulling, because a 2.4.x CLI does not read `_archive/`. (kaotypr/context-circuit-source#209)

Where `record approve`, `record complete`, or `record archive` return
`commit_recommended`, the agent now asks one question: commit and push the
records and ID files it names, or commit only. The person's answer authorizes
that commit and a push of the workspace's base branch to its upstream, that
once; after commit only, the agent says other clones cannot see the records
yet, and with no remote or upstream it commits and says why it could not push.
A push refused because the remote moved on is brought up to date with
`git pull --rebase`, which replays only the person's unpushed record commits:
what Git combines is kept and reported, an ID file conflict keeps the union of
both sides' entries, and any other conflict — the same record changed on both
sides, a record deleted on one side and changed on the other, or a conflict in
a file that is not a record — goes to the person with both versions, the rebase
left in progress. The agent never edits a conflicted record itself, not even to
keep both sides: which version stands is the person's call. `check` follows; a number reserved twice goes to the person.
The agent pushes once more, reports a second refusal or a refusal for any other
reason, and never force-pushes. Teammates' ID file conflicts from upgrading at
the same time are resolved the same way, by the union and `check`. Delivering
code is unchanged: drift there is still explained, not rebased. (kaotypr/context-circuit-source#209)

Four written rules now hold on each host's smallest model where they did not
before (#208):

- A shipped root `.ignore` with `/sources/` keeps `sources/` out of
  ripgrep-based search, including Claude Code's Grep and Glob, and Cursor's
  search; a file named by the person or the task still opens, and `AGENTS.md`
  says to leave the folder out of searches that ignore the file.
- A wrong fact in mounted, borrowed knowledge is neither copied nor corrected
  in `context/`: `AGENTS.md` and `cc-knowledge` say to tell the person the fix
  goes upstream through that repository's own review, and not to edit, clone,
  commit to, or push the borrowed repository.
- `agent setup` turns Claude Code's commit attribution off in the gitignored
  `.claude/settings.local.json`, and `.gitignore` carries that file. The
  orient check names the setting, so a machine without it runs `agent setup`,
  which is how existing workspaces receive it. The agents guide names Cursor's
  personal and team controls; the written no-attribution rule stays the guard
  where neither is set.
- An intent is presented in the language the person writes in, even when the
  record is in its author's; `AGENTS.md` and `cc-intent` say so.

`AGENTS.md` now says that `workspace.yaml`, `members.yaml`,
`member.local.yaml`, and `repositories.local.yaml` sit at the workspace root,
never under `.context-circuit/`. Agents looked for them there, found nothing,
and either searched the workspace or refused to go on for want of a roster. (kaotypr/context-circuit-source#209)

The README's release badges and links point at the forge the template was
published from, GitHub or GitLab.

The worktree reference now says what copy-on-write reuse does with an entry it
cannot reuse: outside `--copy-mode required` it is skipped and reported, and a
rerun skips it again until its source changes, while any other failure, such as
a full disk, stops preparation and keeps what was finished. A Windows file
smaller than one cluster is copied under `auto` and fails preparation under
`required`.

Upgrading a workspace still at schema 2: a 2.5.0 CLI refuses changes to it
unless the pinned CLI runs them. Bring in this template first, then
let the pinned CLI make the ID split through the launcher. One person on a team
makes the split, commits and pushes it, and everyone else pulls before changing
anything.

The worktree reference also names an `npm link` inside node_modules as an
entry reuse rejects, and the `cc-cli` install script now requires the CLI
archive's `LICENSE` to be a regular file, as it already did for the binary,
`README.md`, and `THIRD_PARTY_NOTICES.txt`
(kaotypr/context-circuit-source#169).
