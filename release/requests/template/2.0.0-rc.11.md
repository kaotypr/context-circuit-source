# Context Circuit 2.0.0-rc.11

A candidate for 2.0.0-rc.10, drawn from using it. No record changes shape, no
configuration file moves, and nothing is converted for you. The v2 description in
2.0.0-rc.1 still stands. This template recommends CLI `2.0.0-rc.11`. Git is
required. No Go or Python runtime is.

Two complaints, both about the product being tiring in ways that had nothing to
do with whether it worked.

## Knowledge that nobody wanted to read

Gathering produced accurate notes that were walls of paragraphs with repository
paths dropped into the sentences. The rules said what a note may contain — the
machinery boundary, the anchor form, the catalog entry — and nothing at all about
what a note looks like, so what came out was whatever the model writes by
default. A note like that fails both its readers: a person cannot scan it, and an
agent retrieving it pays for connective prose carrying no fact.

Three changes, in the order they matter.

**Anchors sit in one place.** The body of a note calls things by their project
names, and a closing `Owner:` block says where each one lives. A path dropped
into a sentence stops the reader on a string they cannot act on and lengthens the
sentence around it to explain why it is there. A table pairing paths with what
each one owns carries them just as well, because a column heading does the work
the block does — a sentence never does. The glossary keeps its exception, since
mapping a word to the identifier behind it is that file's whole purpose.

**Form follows content.** A table for things sharing attributes, a diagram where
the relation between them is the fact, bullets for rules that stand alone, a
numbered list for an order, and prose for why it is this way — which is the one
thing prose does better than anything else. A diagram that redraws the list
beside it is noise, and that is written down too.

**The catalog says where a note goes.** Every group carries one line naming what
belongs under it, written before its first entry, so a note has somewhere obvious
to land instead of a guess between two plausible directories.

Plain writing is asked for directly: lead with the answer, one idea to a
paragraph, active voice, the project's own vocabulary, and no sentence that only
restates its heading. Refining a note written by an earlier version is ordinary
work now, with one hard limit — restructuring is not a licence to add facts.
Anchors are confirmed before they survive the rewrite, the reviewed date moves
only on real re-confirmation, and a claim nobody can verify is removed rather
than smoothed into a confident sentence.

## `check` reports shape, not only truth

A note could be accurate, unreadable, and pass. Findings marked `readability:`
now report what a diagnostic can see:

| Finding | Fires on |
| --- | --- |
| Code anchor outside the `Owner:` block | An anchor written into a sentence |
| A paragraph of N lines | A paragraph past eight lines, carrying a list it never made |
| A sentence of N words | A sentence past sixty words |
| No line under the title | A title followed straight by a heading or a list |
| Mermaid diagram type not recognized | A fence whose first word will not render |
| Code fence is never closed | An unbalanced fence |
| An actor note carries numbered stories | A note under `actors/` with none |
| N lines and no section headings | A note past forty lines with no `##` |
| Heading has no line saying what belongs under it | A catalog group with entries but no scope line |
| Notes in X/ are catalogued under two headings | One directory answering to two groups |

Both thresholds came from measurement rather than taste. Run against this
product's own knowledge tree, a sentence limit of forty-five words flagged
seventeen sentences that read perfectly well; at sixty, the four that trip run
from 62 to 84 words. Anchors inside a table were reported until it was clear that
24 of the first 31 findings were owner maps doing exactly the job the `Owner:`
block exists to do.

Anchor detection under-reports on purpose. It requires a slash or a source-file
extension, so an email address and a clone URL are not mistaken for anchors, and
a root file with no extension is missed rather than guessed at.

The findings report and exit, like everything else the diagnostic says. Nothing
blocks on them.

## Knowledge records who the project is for

`actors/` holds one note per person, team, or system that deals with the project,
carrying their standing needs as stories grouped under the business flow each
belongs to. Each group heading links to the `domains/` note describing that flow,
and the flow itself stays described once: an actor note carries only that actor's
stake in it, because a flow retold in every participating actor's note becomes
several copies that disagree.

Stories restart at 1 under each flow and are cited by flow and number. Inserting
one then renumbers that group alone, where numbering straight through a note
would move every story below the insertion and break every citation at once.

A story says what the project does for that actor now. A capability someone wants
is an intent; a wish list kept here rots into a backlog nobody trusts, and takes
the reviewed date's meaning with it. Intent grounding reads the stories of the
actors a request touches, so a request cutting across a standing need becomes a
question for the person rather than a detail settled quietly in a plan.

## A person may change something directly

Every implementation change went through an intent, an approval, planning, and a
worktree. That path exists for one specific risk: an agent's reading of a request
drifting from what the person meant. Where the request already fixes the outcome
— rename this flag, raise this timeout, correct this message — nothing was
derived, so there is nothing derived to approve, and four steps are spent on a
risk that is not present.

`cc-direct` is the twelfth skill and carries that lane:

| | Planned path | Direct lane |
| --- | --- | --- |
| What approves it | The person approves the written intent | The request itself, because nothing was derived |
| Records | An intent and its plans | None; no ID is allocated |
| Where it runs | A prepared worktree on its own branch | The bound checkout, on its current branch |
| What it leaves | Committed work a dependent plan can start from | An uncommitted diff, unless a commit is authorized |
| Knowledge | Reconciled at completion | Reconciled the same way, asked for by repository |

**The person routes, not the agent.** The entry instruction says the agent may
offer the lane where a request is already its own specification, and never takes
it unasked. That asymmetry is the same lesson worktrees already taught: an agent
weighing ceremony against convenience mid-task reliably chooses less ceremony,
which is why preparing a worktree stopped being a judgment call. Leaving the
routing with the person keeps the bypass a decision someone made rather than a
habit an agent formed.

The lane stops as soon as the outcome is no longer settled — a second repository,
a decision nobody has made, a fix revealing the real problem is elsewhere, or
reading large enough to have been a plan. Stopping means saying what was found
and offering the intent, with correct work left in place. A change that grew past
the lane and was carried through anyway is an unrecorded feature nobody approved.

Nothing else relaxes. Committing in a bound checkout, pushing, opening a pull
request, merging, deploying, publishing, and deleting each still need the same
word from the same person.

## One command changes

`context find` takes `--repo ID` alongside `--query TEXT`, returning the catalog
entries claiming one repository together with `reconcile_required` — what
completion names for a plan, for a change made without one. The obligation never
depended on a record existing; it depends on code having changed. An unknown
repository is refused rather than answered with an empty list, because nothing to
reconcile and nothing found read identically.

## Record format

Records written by 2.0.0-rc.4 and later are read by this candidate unchanged, and
2.0.0 will read them too. A workspace still on 2.0.0-rc.3 or earlier is not
converted and starts fresh.

## Upgrading

Install the CLI, then take this release's `AGENTS.md` and the `.agents/skills/`,
`.claude/skills/`, and `.cursor/skills/` trees into the workspace. An `AGENTS.md`
you customized needs merging rather than replacing. `cc-direct` is a new skill
directory in all three trees.

`context/INDEX.md` changed, and a workspace that already has one keeps it: take
the new guidance into your own catalog by hand, or leave it and read the shape
rules in `cc-knowledge` instead. Nothing rewrites a catalog you have edited.

Existing notes are not migrated. Running `check` after upgrading will report
findings against knowledge gathered by earlier candidates — that is the point of
them, and nothing breaks while they stand. Refining a note is a request like any
other, and `cc-knowledge` carries the limits that keep a rewrite from inventing
facts.

`agent setup` is not required by this release. No role definition or brief
changed.

## Candidate status

The shape rules were validated against the only tree available to test them on:
this product's own knowledge. It reported 35 findings against itself, and all 35
were real — eleven prose anchors, eleven overlong paragraphs, five catalog groups
with no scope line, four missing thesis lines, and four sentences past sixty
words. Fixing them is in this candidate, and both thresholds were calibrated on
that run rather than chosen in advance.

Restructuring prose is where facts go missing, which that rewrite demonstrated
twice: two rules fell out of paragraphs becoming lists and were recovered only by
diffing every rewritten paragraph against its original. The limits written into
`cc-knowledge` come from that, not from principle.

Deterministic tests cover each finding in both directions, including the
negatives that keep the anchor rule honest — an email address, a clone URL, a
table cell, a fenced example, the glossary. The catalog checks are covered, and
so is the repository-scoped reconciliation.

**What no test establishes is whether an agent follows any of this.** Whether a
note comes out readable, whether the direct lane is offered rather than taken,
and whether a refusal to grow past the lane actually happens are all claims a
deterministic test cannot make. `cc-direct` has not been exercised in a recorded
session on any host. Exercise the flows you rely on before depending on this
release.
