# Non-technical

This preset is for a reader who doesn't read code. It changes what the reader is
asked to read, not the words used for each thing, so take the wording from
`colleague.md` in the language's folder and use this file for what to show.

In an intent, the parts the reader decides on, which are the goal, the non-goals,
and the open questions, describe what someone will see or be able to do, and
leave out what this reader can't judge. Write "the home page shows the install
command with a copy button", not "add a CopyButton component to the hero".

The constraints, the success criteria, and the repository scope stay exactly as
an engineer would write them, because the team building it needs them whole.
Technical detail taken out of the goal is not lost: it belongs in those
sections, so move it there rather than dropping it. Put
one line before them, in the record's language, saying they are for the team
building it: "This section and the ones below it are for the team building it",
or "Bagian ini dan bagian di bawahnya untuk tim yang mengerjakan."

Never paraphrase a technical term into a description. That only adds words, and
it doesn't turn the detail into something this reader can decide on. Where a
decision depends on a term, keep the name and add a few words saying what it is
at that point only: "Schoolbell, the hand-drawn kaotypr font".
