# Verification

## Verification strategy

- Validate every new and revised JSON contract with positive, missing-field, invalid-reference, contradiction, and backward-compatibility fixtures.
- Verify a large synthetic application with many domains, roles, menus, and workflows resolves a bounded task context containing only the selected product map, affected role, domain, workflow, and repository instructions.
- Verify role pages can express full cross-domain user stories while exact rules remain owned by linked workflow pages and reference validation catches broken links.
- Verify initialization can create a minimal baseline, preserve explicit unknowns, and leave an existing wrapper without Product Knowledge valid.
- Verify gather-context discovery is read-only toward canonical context and stores only credential-free candidates, gaps, contradictions, and context packages in ignored runtime state.
- Verify plan and planless flows classify Product Knowledge impact, preserve proposed behavior outside current workflow pages, and deliver the same context revision to worker and verifier inputs.
- Verify unexpected worker or verifier impact blocks silent synchronization and is retained for human review.
- Verify canonical workflow and role pages change only after explicit effectiveness confirmation, while merged but inactive changes remain contribution evidence.
- Verify onboarding packs are reproducible from one Git revision, list their included source paths, and are clearly marked as generated views.
- Run type checking, workspace and document validation, the complete automated test suite, template packaging checks, and manual Codex/Claude host-parity proofs.
