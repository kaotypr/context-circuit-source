## Intended behavior

The assembler builds the `context-circuit-template` artifact by staging only the
template-owned allowlist, rejecting any file outside it so source design, tests,
harness, scripts, the release ledger, plans, Product Knowledge, runtime
evidence, credentials, and local bindings never enter the artifact. Upgrade
migrations replace the machinery, runtime code, contracts, and role guidance
while preserving workspace-owned state and reporting migration-needed when a
change alters the meaning of a plan, context unit, or runtime record.

## Concrete change and affected surfaces

Implement `scripts/release-artifact.sh` (and `scripts/build-dist.sh`) to
assemble the artifact from the current source checkout enforcing the
template-owned allowlist derived from the REL-001 boundary; assembly is
deterministic and stops at `remaining_gate: publication` without pushing. Author
upgrade migrations under `wrapper/migrations` that replace template-owned files
and preserve project identity, accepted Product Knowledge, sources/provenance,
plans and plan status, local bindings, connected repositories, and runtime
evidence. Assembly excludes the source-side `release/` ledger and every
never-ship surface.

## Inputs and outputs

Inputs: the release boundary in `wrapper/manifest.yaml`, the staged inventory in
`scripts/release-manifest.txt`, and the current source tree. Outputs: an
assembled template tree containing only allowlisted files, and upgrade
migrations under `wrapper/migrations`.

## Risks and open questions

- The allowlist must be exact: a file outside it reaching the artifact violates
  REL-AC-03 and the assembly boundary (INV-SEC-01).
- Migrations must never overwrite user state; a preserved-file list that drifts
  from the boundary silently loses user work on upgrade.
