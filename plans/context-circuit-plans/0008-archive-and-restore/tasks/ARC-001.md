## Intended behavior

Archiving moves `plans/<id>/` to `plans/archive/<id>/`, drops the plan's row from
the active index, and preserves all plan files, human status, and runtime
evidence exactly. It performs no status or execution validation and implies no
completion, delivery, cleanup, or deletion. Restore is the only way back to the
active area, and normal orientation never reads or traverses `plans/archive/`.

## Concrete change and affected surfaces

Add `plan_archive` and `plan_restore` primitives to `wrapper/runtime/engine.sh`.
Each acquires a short-lived plan-organization lock (distinct from the execution
lock), checks only the exact source/target paths and index collisions, then
updates the plan directory and `plans/INDEX.md` as one recoverable operation. A
failed move or index write leaves the original directory and index entry intact.
Neither operation reads plan status or execution status.

## Inputs and outputs

Inputs: a named plan ID and the current active index. Outputs: the plan directory
moved between `plans/<id>/` and `plans/archive/<id>/`, an atomically updated
`plans/INDEX.md`, and a structured result with a reason code; on collision or
failure, no files change.
