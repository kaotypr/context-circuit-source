## Intended behavior

A failed verification routes back to the same worker for a repair, which is
always a new commit and never an amendment. The worker failure counter
increments once per rejection; the initial implementation counts as attempt one,
and execution stops at the third failure preserving all evidence, with no
automatic fourth attempt. A blocked execution is distinguished from an invented
worker failure and does not increment the counter as if the worker failed.

## Concrete change and affected surfaces

Add attempt and failure-counter management to `wrapper/runtime/engine.sh`:
route failed verification ids and evidence to a new repair attempt, increment
worker_failures per rejection, enforce the three-failure stop, and keep blocked
outcomes separate from worker failures. A repair that would require new scope
stops execution rather than redesigning the plan.

## Inputs and outputs

Inputs: a failed verifier result with failure ids and evidence, the latest
commits, and the remaining failure count. Outputs: an incremented failure
counter, a new repair attempt record, or a terminal failed execution status at
three failures.
