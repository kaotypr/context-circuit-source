## Intended behavior

Approval is a conversational gate that changes only status, from draft to
approved, and only after deterministic readiness checks (accurate objective,
explicit repository mappings, no task depending on an unknown repository,
resolved or accepted context conflicts, testable acceptance and verification,
bounded scope). There is no confirmation card. An unapproved plan cannot begin
execution. The execution and worker-handoff record shapes are defined so
downstream tasks write evidence in a stable form.

## Concrete change and affected surfaces

Implement plan-approve in `wrapper/runtime/engine.sh` as an atomic
draft-to-approved transition guarded by the readiness checks. Author
`wrapper/contracts/schemas/execution.yaml` (the minimal execution record:
execution id, plan, plan revision, status, worker_failures, repositories,
attempts) and `wrapper/contracts/schemas/worker-handoff.yaml` (commits, tasks,
tests, assumptions, limitations, verifier focus, repair flag), both stored under
`.runtime/`.

## Inputs and outputs

Inputs: an approved-ready draft plan. Outputs: an atomic status transition to
approved, and two record schemas that later tasks populate.
