## Intended behavior

The workspace has a seeded context tree with `context/INDEX.md` as the agent
retrieval catalog and human navigation aid, so an agent selects knowledge units
by concept without reading the whole tree. The `context/proposals/` area holds
pending, un-accepted updates; a pending proposal never mutates accepted knowledge
implicitly.

## Concrete change and affected surfaces

Author `context/INDEX.md` following the CTX-001 index schema: list each unit by
page path, context id, topic, summary, keywords/aliases, related domains and
repositories, decisions/constraints, status, owner, freshness, and primary
provenance, and index pending proposals and stale warnings by target context id,
related plan, topic, repository, and impact status. Establish the
`context/proposals/` directory as the store for reviewable, un-accepted updates
(INV-KNOWLEDGE-02), kept separate from accepted pages so completion,
verification, or a worker claim can never silently accept a proposal.

## Inputs and outputs

Inputs: the context schemas from CTX-001 and the source-side Product Knowledge
units. Outputs: the seeded `context/INDEX.md` retrieval catalog and the
`context/proposals/` area for pending updates.
