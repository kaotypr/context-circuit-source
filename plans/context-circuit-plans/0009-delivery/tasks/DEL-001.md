## Intended behavior

Pull-request creation, merge, push, and deployment are separate human-requested
actions, never inferred and never a side effect of verification or completion. A
pull request sources each execution branch (`cc/<plan-id>/<repository-id>`) and
targets that repository's recorded `anchor_branch`, never `default_branch` and
never a moving remote. Delivery blocks and reports when the source branch,
provider/remote, or target branch is unavailable rather than inferring a remote.

## Concrete change and affected surfaces

Define the delivery boundary as a distinct explicit action in
`wrapper/adapters/WORKFLOW.md`. In `wrapper/runtime/engine.sh`, compute the
source (execution branch) and target (recorded anchor branch) for a PR and return
a blocked result with a reason code when a source, provider, or target is
unavailable. The runtime itself performs no push, merge, publish, or deploy;
opening the PR is a host/delivery action.

## Inputs and outputs

Inputs: an explicit human delivery request, the execution record's branches and
recorded anchor branches, and remote/provider availability. Outputs: computed
source/target per affected repository for the PR, or a blocked-delivery result
naming the missing source, provider, or target.
