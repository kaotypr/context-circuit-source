# Define filesystem-only execution and exclusive worktree ownership

## Description

Define plan execution so a worker must hold the plan lease and an exclusive plan-scoped worktree using only coordinator and worker instructions and the filesystem runtime contract.

## Implementation scope

- docs/run-task.md
- docs/runtime-contract.md
- docs/agent-workspace-workflow.md
- workspace.yaml
- agents/repository-worker.md

## Test scope and expectations

- docs/runtime-contract.md
- docs/agent-workspace-workflow.md
- test
- .runtime/*

- Different plans can execute concurrently with distinct runtime identities, leases, branches, and worktrees.
- Same-plan lease contention is deterministic and non-destructive.
- The filesystem protocol is the user-facing entry contract and does not depend on a command adapter.
- Base checkout, other plan worktrees, wrapper config, and activity state are protected from worker writes.

## Verification commands

- git diff --check
- `sh test/acceptance.sh`

## Acceptance criteria

- A worker cannot start or continue plan execution without a valid lease and assigned worktree.
- The acceptance suite can replay ownership and isolation without invoking a Node or JavaScript command.
