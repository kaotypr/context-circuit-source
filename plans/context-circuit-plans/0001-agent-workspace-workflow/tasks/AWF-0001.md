# Establish the normative Agent Workspace contract

## Description

Review and make internally consistent the workspace entry contract, authority rules, context index, role instructions, and approved workflow specification so every session can orient from the same durable instructions.

## Implementation scope

- AGENTS.md
- WORKFLOW.md
- context/INDEX.md
- context/PROJECT.md
- context/ARCHITECTURE.md
- context/CONVENTIONS.md
- context/DECISIONS.md
- agents/coordinator.md
- agents/repository-worker.md
- agents/reviewer.md
- docs/agent-workspace-workflow.md

## Test scope and expectations

- AGENTS.md
- WORKFLOW.md
- context/INDEX.md
- docs/agent-workspace-workflow.md

- A reader can identify instruction precedence, session roles, runtime locations, ownership boundaries, human gates, and handoff requirements without consulting the legacy command reference.
- The normative documents do not instruct a user to invoke node or cc.mjs as the primary workspace entry point.
- The contract clearly distinguishes intended replacement behavior from the still-preserved legacy implementation.

## Verification commands

- git diff --check
- node .agents/bin/cc.mjs validate

## Acceptance criteria

- The full workflow specification and the short entry documents agree on root sessions, child sessions, concurrency, leases, worktrees, handoffs, and gates.
- An independent reviewer can trace every required runtime artifact to a documented owner and lifecycle.
