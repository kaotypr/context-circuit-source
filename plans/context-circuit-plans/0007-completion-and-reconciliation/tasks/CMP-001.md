## Intended behavior

A verified execution produces completion evidence but never marks a plan done on
its own; only an explicit human request moves the plan to done, and only when the
latest execution passed independent verification. Marking done preserves the
execution evidence and writes an implementation completion record capturing full
provenance.

## Concrete change and affected surfaces

Author the completion record shape in `wrapper/contracts/schemas/completion.yaml`
and implement completion-eligibility and record-creation primitives in
`wrapper/runtime/engine.sh`. Eligibility checks the latest execution ID and its
commit set and requires a passed verifier outcome; only `passed` satisfies
verification (not `waived`, `blocked`, or `failed`). On the done transition the
runtime records the completion record and preserves prior execution evidence.

## Inputs and outputs

Inputs: the latest execution record, its verifier result, latest commit set per
repository, plan revision, and the human completion request. Outputs: the plan
status transition to done and an implementation completion record recording plan
revision, execution ID, commits, verifier result, and the human request.
