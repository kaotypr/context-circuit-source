## Intended behavior

`cc-publish` is a read-as-procedure skill (INV-SKILL-01), invoked by name or
`/cc-publish <plan-id>`, that publishes a publication per the `kind` in its
`config.yaml`. The plan kind reads a plan and its tasks and reflects them onto an
external tracker one-way: plan -> work-item, task -> child-item, with
self-contained external text. Re-running updates the same external items in place
via each task's `synced_digest`, never duplicating.

## Concrete change and affected surfaces

Author `.agents/skills/cc-publish/SKILL.md` with kind dispatch and the plan-kind
procedure: preflight the provider (discover statuses, checklist capability), map
plan->work-item and task->child-item, express `depends_on` and
`plan_dependencies` as sibling dependency links (never nesting), leave task type to
the human, and author self-contained descriptions plus acceptance/verification as
checklists (or description-checklist). Apply the `[<plan-number>] <plan title>`
parent and `<task-number> · <task title>` child title convention. Honor optional
`instructions` for language, tone, and best-effort optional-field enrichment. Route
all provider/network calls through the host/MCP layer; write the record via the
runtime's atomic write under `publication/<name>/published/`.

## Inputs and outputs

Inputs: `config.yaml`, the named `plans`/`tasks` artifacts, the prior record (if
any), and provider capabilities via host/MCP. Outputs: created or updated external
work items and an updated per-plan record keyed by `synced_digest`. Status flows
out of `plan.yaml` only; nothing is written back to the workspace.
