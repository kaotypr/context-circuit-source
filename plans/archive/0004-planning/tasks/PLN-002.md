## Intended behavior

The runtime allocates plan ids as `NNNN-<kebab-slug>`, always the next value
after the highest ever allocated, so an id is unique for the workspace lifetime
and never reused. Plan validation checks structure, that every task maps only to
declared repositories, and that task dependencies form a valid order; a task
naming an undeclared repository or an unknown dependency is rejected. The active
`plans/INDEX.md` rows are maintained deterministically.

## Concrete change and affected surfaces

Add plan-allocate-id, plan-validate, and active-index maintenance operations to
`wrapper/runtime/engine.sh`. These are deterministic support operations returning
structured results and reason codes; they do not write plans or interpret
Product Knowledge. Index maintenance updates `plans/INDEX.md` active rows without
reading plan or execution status.

## Inputs and outputs

Inputs: a plan directory / plan.yaml conforming to the PLN-001 schema, and the
existing set of allocated ids. Outputs: a newly allocated unique id, a
pass/fail validation result with reason codes, and deterministically updated
active index rows.
