## Intended behavior

The same host-neutral scenario library runs against each product host adapter
(Codex CLI, Claude Code, Cursor Agent) through a thin per-host binding that
covers only what genuinely differs: spawning the coordinator, mapping a native
child to the worker/verifier packet, the human-simulator definition location,
and file-access/usage trace capture. An opt-in matrix runner iterates
{scenario x host} and prints a summary keyed by (scenario, host), recording each
per-host verdict, the trace-availability flag, and the mapped acceptance criteria
and invariants.

## Concrete change and affected surfaces

Under `template-harness/human`, add the host-native human-simulator definitions
carrying the same persona contract for `codex` and `cursor-agent` (the
`claude-code` definition is `.claude/agents/cc-human-simulator.md`), and the
per-host spawn and trace-capture bindings. Extend the runner to accept
`--host codex | claude-code | cursor-agent` (default = the driver host) and add an
opt-in matrix runner over {scenario x host}. Where a host exposes the per-child
trace, dimension C is a hard gate and D is recorded; where it does not, C
degrades to best-effort transcript inference (warning) and D is reported
unavailable. The matrix runner stays outside the deterministic acceptance gate.

## Inputs and outputs

Inputs: the scenario library, the host adapter under test, and each host's native
spawn/trace primitives. Outputs: the per-host human-simulator definitions and
bindings, and a matrix summary keyed by (scenario, host) with a
trace-availability flag.

## Risks and open questions

- The summary must record trace availability so a "pass" is never mistaken for
  "audited" when the host could not provide the trace (SCN-AC-02).
- Exact Codex/Cursor definition paths are fixed against the current host CLIs;
  the persona contract does not change across hosts.
