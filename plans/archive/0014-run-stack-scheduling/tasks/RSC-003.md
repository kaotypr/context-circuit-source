## Intended behavior

Delivery stays separate, explicit, per repository, and per plan, targeting each
repository's recorded `base_branch`. v0.6 adds a drift guard: when a plan is
delivered and its recorded base has diverged from the current `base_branch` tip
(because a sibling plan already merged), the plan is rebased onto the current tip
and re-verified before its pull request opens (INV-DELIVER-01 extended). A plan is
never merged from a base that no longer reflects the branch it will land on.

## Concrete change and affected surfaces

In `wrapper/runtime/engine.sh` detect base divergence at delivery (recorded base
versus current base tip) and, when drifted, rebase onto the current tip and
re-verify before the PR opens. In `wrapper/adapters/WORKFLOW.md` reflect the drift
guard in the delivery action and delivery order — a single-repository stack merges
as one serialized rebase train, a multi-repository stack as one short train per
repository, with failed and held plans reported as not delivered and the reason
attached.

## Inputs and outputs

Inputs: a verified plan's recorded base, the current `base_branch` tip, sibling
merge state. Outputs: a drift decision (rebase + re-verify or proceed), an
up-to-date base before the pull request opens, and dependency-ordered delivery
reporting.
