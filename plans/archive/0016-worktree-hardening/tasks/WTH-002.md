## Intended behavior

When a writer hits repository friction its guidance did not cover, the failure
becomes a durable improvement to the repository's own agent docs rather than a
CC-side profile. The worker handoff carries a `repository_friction` note, and
reconciliation routes it to a proposal on the repository's own agent docs (a
normal plan targeting its `AGENTS.md` / skills) — never core Product Knowledge. The
next writer then reads the improved guidance via discovery.

## Concrete change and affected surfaces

Add a `repository_friction` field to `wrapper/contracts/schemas/worker-handoff.yaml`
capturing "the repo's guidance did not cover X". In `wrapper/runtime/engine.sh`
route that note through the reconciliation flow into a proposal on the
repository's own agent docs, keeping it out of core context and preserving the
reference-not-capture principle.

## Inputs and outputs

Inputs: a worker handoff reporting uncovered repository guidance. Outputs: the
`repository_friction` field on the handoff schema, and a proposal targeting the
repository's own `AGENTS.md` / skills produced through reconciliation (never a
CC-side profile or core-context capture).
