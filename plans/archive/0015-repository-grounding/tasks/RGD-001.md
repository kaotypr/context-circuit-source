## Intended behavior

During worktree preparation — right after the runtime creates the worktree from
its execution base — a deterministic runtime function scans that exact checkout
for the repository's own agent guidance and emits a grounding manifest. It is a
filesystem scan plus a small frontmatter read: it emits data, not prompt text
(INV-RUNTIME-01). Because it scans the base (which under the run-stack scope may
be a stacked predecessor branch or integration merge), bootstrapped guidance
propagates through a stack. A doc-less repository yields a valid empty manifest.

## Concrete change and affected surfaces

Add `cc_discover_repo_grounding <worktree>` to `wrapper/runtime/engine.sh`,
scanning a host-neutral set: `AGENTS.md`, `CLAUDE.md`, `.cursor/rules/**`,
`.github/copilot-instructions.md`, and `.agents/skills/*/SKILL.md` (reading each
skill's `description:` frontmatter to build a menu). Author
`wrapper/contracts/schemas/grounding-manifest.yaml` with `files[]`,
`skills[]{name, description}`, and `environment`. Record the manifest snapshot in
`wrapper/contracts/schemas/execution.yaml` as execution evidence for
reproducibility.

## Inputs and outputs

Inputs: the prepared worktree checked out at the execution base. Outputs: the
grounding manifest (present files, skill name+description menu, environment
placeholder), and the manifest snapshot recorded in the execution record. An
empty repository yields an empty-but-valid manifest.

- The scan set is a runtime constant (extensible), not per-repo configuration;
  discovery must stay deterministic and emit only data, never captured prose.
- The `environment` field is set by worktree hardening (plan 0016), not here.
