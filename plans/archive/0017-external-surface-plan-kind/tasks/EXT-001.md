## Intended behavior

The external surface is a set of opt-in, manually-triggered publications that are
orthogonal to the core workflow. No plan/approve/execute/verify/deliver phase,
runtime action, coordinator route, or role references, triggers, waits on, or is
affected by a publication, and none runs except on an explicit human invocation of
cc-publish. The word "publish" belongs to the external surface only; git delivery
speaks in its own terms so the two never share a word.

## Concrete change and affected surfaces

Add INV-EXTERNAL-01 (isolation), INV-EXTERNAL-02 (data boundary, export-only,
nothing under `plans/`), and INV-EXTERNAL-03 (self-contained external artifacts) to
`wrapper/contracts/invariants.yaml`, with their `owners:` map entries (the
`external_surface` concern and the cc-publish trigger under existing INV-SKILL-01).
Apply the wording-only vocabulary split: vacate "publish"/"publication" from the
git-delivery side in INV-DELIVER-01, INV-RUNTIME-01, the `runtime.excludes` list in
`wrapper/manifest.yaml`, and AC-16, rewording them to "push" / "open a pull
request". This changes no behavior, version, or authority.

## Inputs and outputs

Inputs: the existing invariant set and manifest. Outputs: three new invariants plus
owner-map entries, and the reworded git-delivery invariants/manifest text. No new
authority is granted; git delivery still requires the same separate human actions.
